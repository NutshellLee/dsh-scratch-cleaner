# dsh-scratch-cleaner

[English](./README.md) | 中文

一个 DeepSeek Harness 宿主插件：给智能体一个专门放临时脚本的地方，并在每一轮结束时把这个地方清空。

一句话概括：零配置、不要密钥、不下模型——装上之后，工作区就不再收集一次性脚本。

## 前后对比

没有这个插件时，一天的智能体工作长这样：

```
project/
  src/…
  probe-config.mjs        ← 为了回答一个问题写的
  probe2.mjs              ← 上个答案不对，于是又探了一次
  check-final.mjs         ← 大概"最终"了十分钟
```

装上插件之后，同样的一天长这样：

```
project/
  src/…
  .dsh-scratch/           ← 每轮结束被清空
```

而且每次回合结束都会说清删了什么：

```
scratch-cleaner: turn 12 deleted 3 entries from D:\project\.dsh-scratch: probe-config.mjs, probe2.mjs, check-final.mjs
```

## 问题从哪来

你让智能体去查一件事，它就会写个脚本：探一下配置文件、给某个别扭的接口写个一次性验证、写个临时驱动去验证一个假设。这正是你想要它做的事，也正是干净的仓库悄悄堆满 probe.mjs、probe2.mjs、check-final.mjs 的原因。

比普通杂物更麻烦的是三点：

第一，你分不清哪些是垃圾。上周验证假设的脚本，和明天修 bug 要用的脚本，长得一模一样。

第二，手动删每次都要做判断，于是要么拖到很晚，要么干脆不删。

第三，按规则删很危险。所谓"删掉一天内没被引用过的文件"，早晚会删掉真东西。

## 代价与收益

先说代价，不夸大——它是个小插件，不是性能优化工具：

每轮结束时读一次目录、删掉目录里的东西；回合进行中它什么都不做，所以清理从不拖慢智能体本身的工作。

没有文件监听、没有轮询、没有常驻进程、没有索引、不联网，运行时也不需要解析依赖（schema 依赖已经打进构建产物）。

开销被限制在一个目录内，与工作区大小无关，也不会遍历整个项目树。

再说收益：

工作区保持项目本身的体量，遍历目录的工具——文件搜索、编辑器索引、diff——不再把一次性脚本算进去。

后续回合不再读到智能体自己写过的过期探针，上下文里剩的是工作本身，而不是脚手架。

不需要做任何分类：没有扫描、没有按时间猜的规则，也就没有猜错的余地。

在提示词里写几句提醒有点用，但用处有限：工作区里最后还是两种文件混在一起，没有任何东西能把它们区分开。

## 思路

不要再试图"认出垃圾"。给临时工作一个位置，再让这个位置本身是临时的：

第一步，在系统提示里告诉智能体：临时脚本放在工作目录下的 .dsh-scratch 里。第二步，一轮结束时，把这个目录里的东西删掉。

约定负责分类，目录负责圈定范围，回合结束负责清理。需要留存的脚本，按定义就不是临时脚本，自然不会进那个目录；而进了那个目录的，不必逐个检查就可以删。

## 它小心在哪里

只碰一个目录：只读取并删除所配置的临时目录的直接子项。散落在工作区的探针脚本一个都不动——智能体不遵守约定时，这个插件清理不了，它也不假装能。

回合结束才清理，不在回合中间：那一轮产生的回答仍然可以引用它写过的脚本。

会把做过的事说出来：默认开启日志，每轮结束打印删掉了哪些名字，清理是可追溯的，不是神秘的。

不猜工作目录：路径来自会话头信息，没有工作目录的会话直接跳过。

一个失败不影响其余：某个条目删不掉时，其余照常处理，下一次回合结束再重试。

删除是立即且最终的：没有回收站，没有保留期。这正是它的意义——值得留下的东西不该放在临时目录里。

## 安装

```sh
# 从 npm 仓库安装
dsh plugin add @nutshelllee/dsh-scratch-cleaner

# 或从本地检出安装
dsh plugin add link:/absolute/path/to/dsh-scratch-cleaner
```

然后在 profile 清单（`dsh.profile.bundles`）里启用它并重启应用，宿主半体才会加载。在 DSH 桌面版里，也可以直接在插件页按包名安装。

## 配置

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `scratchDir` | `.dsh-scratch` | 临时目录名，在每个会话的工作目录下解析。 |
| `logReclaimed` | `true` | 每轮结束时打印一行，列出被删除的条目。 |

在 profile 补丁里按同一行 id 覆盖：

```yaml
- id: scratch-cleaner
  config:
    scratchDir: .probe
    logReclaimed: true
```

## 自检

```sh
node test/scratch-cleaner.test.mjs
```

九个行为测试都跑在隔离出来的临时工作目录上，不碰真实会话。覆盖默认值、自定义目录、嵌套目录树、空目录、目录不存在、会话没有工作目录，以及最要紧的那条：临时目录旁边散落的脚本必须被保留。

## 重新构建

`lib/index.js` 是可读源码，`lib/plugin.js` 是加载器真正导入的构建产物，里面把 schemastery 打进去了，因此 profile 安装时不需要在加载期解析任何依赖。

```sh
node build.mjs
```

## 限制

- 删除是最终的。后续回合还要用的脚本，不要放进临时目录。
- 约定被忽略时插件无能为力：智能体把探针写在别处，它们就留在别处。
- 删不掉的条目会在下一次回合结束重试；失败会记日志，不会静默。
